# v4.1.1-bugfix.1 修复测试版

这是从 v4.1.1 修复分支构建的预发行包，用于 Windows + VRChat 实机回归。使用完整 ZIP，解压到独立目录后启动 `VRChatDanceAssistant.exe`；保留 `_internal` 等全部文件。不要直接覆盖正式版目录。启动前备份配置、统计、收藏和视频目录；程序默认使用当前用户的数据，换一个解压目录不会自动隔离已有数据。

## 本轮修复

- 统计备份增量导入保留本地已有修订，优化长历史区间计算，修复夏令时日期边界。
- 界面与自动测速共用 CDN 收藏，迁移旧记录一次并保留旧文件。测速期间手选节点或关闭自动优选后，旧任务不会覆盖选择。
- 持续慢速连接更早进入复测；后台下载遵守并发上限，保留播放缓存优先级、去重和取消行为。
- 修复缺少日志目录时分段请求无法完整缓存、旧 YouTube 文件阻挡 CDN 预载、停止后旧任务重新入队。
- 修复 WannaDance 收藏被旧日志覆盖，DuDu 曲库来源错位和未下载收藏被过滤；曲库关闭后释放窗口，批量取色减少重复工作。

## 建议实测

1. 在 PyPyDance、WannaDance、DuDu 中分别确认当前歌播放、后续预载和永久保存。DuDu 需先按程序提示启用并确认本机证书。
2. 收藏一个 CDN，重启后运行快速测速，检查收藏仍在；测速过程中换节点并应用，确认结果返回后保留手选项。
3. 开启并行预载，确认下载数量与配置一致、当前播放正常；停止服务再启动，确认不会下载上个会话留下的队列。
4. 多次打开、关闭曲库，切换 DuDu 和 WannaDance，确认来源、缺失曲与收藏筛选一致。
5. 使用备份副本测试统计导入，确认本地修改没有被旧备份覆盖；检查长时间段报告和 CSV 导出。
6. 确认 SteamVR 面板、自启和 Cool Down；正常退出后检查服务和 hosts 恢复。

反馈请附版本号、房间、复现步骤、运行日志及是否使用旧数据。自动化测试与打包演示不代替真实 VRChat、SteamVR/UAC 和 hosts 恢复的人工验收。
