# v4.4.5 发布验证

本版本用于 Windows + VRChat 发布前回归。使用完整 ZIP，解压到独立目录后启动 `VRChatDanceAssistant.exe`，并保留 `_internal` 等全部文件。不要把测试目录与正式版混用；程序默认使用当前用户的数据，换一个解压目录不会自动隔离已有数据。开始前请备份配置、统计、收藏和视频目录。

## 本版重点修复

- 永久曲库命中不再修改文件修改时间，避免已压缩歌曲被误认为原片更新而重复压缩。
- 压缩、分类整理和平铺曲库时同步维护 CoolDown 路径；正在使用的 CoolDown 文件不会被压缩或移动。
- 大队列压缩降低进度写盘频率，限制界面详情复制量，避免上万首任务被界面和 JSON 写入拖慢。
- 启动时优先显示上次成功统计，后台分区域刷新，索引扫描不再阻塞启停服务。
- 精简内置 FFmpeg，保留 CPU、NVIDIA、AMD 和 Intel 编码能力，减小发行体积。
- 新增 DuDu 最新活动预载，按活动顺序去重下载，忽略占位编号并复用现有下载队列。
- 启用 DuDu 证书后可在启动时检测新活动，支持询问/自动缓存、同日内容签名、缺失歌曲去重和活动次日 00:00 前保护；未启用证书时不请求活动接口。
- 高级模式支持自定义 HTTPS 活动接口、恢复默认地址，以及是否允许活动文件在保留期内超过临时缓存上限。严格上限模式先清普通缓存，不足时暂停活动剩余预载，不影响正常播放下载。
- 修正曲库压缩剩余时间把单首工作量误作累计基准的问题；近期速度按真实累计增量计算，并随窗口和样本数平滑提高权重，避免分钟级严重低估和硬切换跳动。
- 保留实测较优的 ETA 加权框架，新增分析/编码/校验阶段耗时和完成时间；编码后跳过及校验失败计入速度统计，直接跳过不计入，校验不再混同于编码 99% 进度。
- 收益不足跳过仅在同参数且原文件未变时保留，不再中断后盲目重试；参数变化会重新排队，处理顺序改为未处理歌曲、失败/取消重试、跳过。
- 自动活动结果返回途中关闭证书、策略或服务时不再误触发下载；跳过判断同时比较编码器，CPU 与 GPU 参数不再混为同参数。

## 必做实测

1. 分别进入 PyPyDance、WannaDance、DuDu FitDance，确认当前播放、后续预载、永久保存和回源行为。DuDu 需先按程序提示启用并确认本机证书。
2. 在 DuDu 存储页将“活动歌单预载策略”分别设为询问、自动缓存和关闭检测，重开软件验证活动名称、歌曲数量、队列顺序及已有文件跳过；跳过后不重复提示，同日内容更新能重新识别，未启用证书时不请求活动接口。高级模式检查“歌单接口”自定义与恢复默认，并在严格上限和允许超限两种模式下验证容量不足行为及次日 00:00 前保护。
3. 将一首曲库歌曲设为 CoolDown，分别测试压缩、分类整理和平铺，确认放松视频仍可播放。启用 CoolDown 后，确认对应文件不会被压缩或整理。
3. 已压缩歌曲播放后再次打开压缩选择器，确认不会仅因播放而重新排队；真正替换原文件后仍应重新压缩。
4. 使用大批量歌曲运行压缩，检查并行任务、暂停、继续、取消和退出；展开处理详情，确认界面不会逐首重建全部历史文本。持续观察预计剩余时间，确认不再把数小时误报成几分钟，且近期与全程速度切换时没有剧烈跳变。中断后重新开始，确认同参数收益不足歌曲不重复尝试，参数变化才重试，并按未处理、失败/取消、跳过的顺序处理。
5. 启动后先显示上次统计及同步时间，后台刷新时仍可关闭软件。反复进入存储页，确认没有每次都被迫全量扫描。
6. 收藏一个 CDN，重启后运行快速测速，检查收藏仍在；测速过程中换节点并应用，确认结果返回后保留手选项。
7. 开启并行预载，确认下载数量与配置一致、当前播放正常；停止服务再启动，确认不会下载上个会话留下的队列。
8. 确认 SteamVR 面板、自启和 CoolDown；正常退出后检查服务和 hosts 恢复。
9. 分别用 CPU、NVIDIA 和 AMD 编码器实测一首视频；有 Intel QSV 的电脑再验证 QSV。检查分辨率、帧率、实际帧数和音频是否正常。

反馈请附版本号、房间、复现步骤、运行日志及是否使用旧数据。自动化测试与打包演示不代替真实 VRChat、SteamVR/UAC 和 hosts 恢复的人工验收。
